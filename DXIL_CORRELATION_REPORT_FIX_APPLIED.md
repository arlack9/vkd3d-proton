# DXIL Correlation Report Fix - April 16, 2026

## Summary
Fixed the `debug_write_correlation_report()` function to properly traverse all CFG blocks and group SPIR-V operations by their source DXIL instruction IDs, providing accurate correlation analysis and expansion ratio tracking.

## Changes Applied

### File Modified
- `c:\Users\gmr\Desktop\test-build\subprojects\dxil-spirv\dxil_converter.cpp`

### Function Updated
- `void Converter::Impl::debug_write_correlation_report(CFGNode *entry, CFGNodePool &pool)`

## Key Improvements

### FIX #1: Full CFG Traversal
**Before:** Only analyzed entry block
**After:** Traverses ALL blocks using `entry->walk_cfg_from()` lambda

```cpp
entry->walk_cfg_from([&](CFGNode* node) -> bool
{
    // Process each block in CFG
    ...
    return true;  // Continue traversal
});
```

### FIX #2: Group by DXIL Instruction ID
**Before:** One line per SPIR-V operation
**After:** Groups SPIR-V ops by source DXIL instruction to show expansions

```cpp
struct InstructionMapping
{
    uint32_t dxil_id;
    uint32_t dxil_kind;
    uint32_t dxil_op;
    Vector<const Operation*> spirv_ops;  // Multiple SPIR-V ops per DXIL
};
```

### FIX #3: Actual Entry Point Name
**Before:** Hardcoded "MainPS" or pointer address
**After:** Uses real entry point name from `execution_mode_meta.entry_point_name`

```cpp
fprintf(f, "Entry Point: %s\n\n", execution_mode_meta.entry_point_name.c_str());
```

### Additional Enhancements
